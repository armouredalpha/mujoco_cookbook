Part 1 — MuJoCo Basics: The Cube Warm-Up

1.1 Launching the Simulator

Launch the sample scene to get familiar with the MuJoCo interface.

terminal
cd ~/ros2_ws/mujoco/bin ./simulate ~/ros2_ws/mujoco_course_files/mjcf_basics/simple_scene.mjcf

Expected Output:

The application window has three distinct parts:

  • Menu Panel (Left) — all configuration for the MuJoCo application and the simulation scene.
  • Simulation Scene (Center) — the environment where the robot and other objects live.
  • Joints and Controls Panel (Right) — shows estimated current joint positions and graphical sliders for joint control. Sub-menus here usually open in a collapsed view by default.

1.2 Activity: Apply Force and Torque

MuJoCo lets you manipulate a model in the scene using simulated translational (force) or rotational (torque) forces.

Selecting a part:

  • Double-click a model part to select it (it highlights).
  • Double-click anywhere outside the model (e.g., the ground plane) to deselect.
Note Watch the orange-yellow cube brighten from dark to light yellow when selected.

Force Testing

To apply a linear force (translate the model along any of the 3 axes):

  1. Double-click the part to select/highlight it.
  2. Hold Ctrl, right-click on the part, and drag in the desired direction.
  3. A red line appears showing the direction of applied force.
Shortcut Ctrl + Right-Click + Drag

Torque Testing

To apply an angular force (rotate the model along any of the 3 axes):

  1. Double-click the part to select/highlight it.
  2. Hold Ctrl, left-click on the part, and drag in the desired direction.
  3. A red box/arc appears showing the direction of applied torque.
Shortcut Ctrl + Left-Click + Drag
Tip You can adjust the magnitude of force/torque applied via the Force and Torque values in the Map sub-menu under the Visualization menu.

Understanding the Robot Base MJCF

  • The <mujoco model="robot_base"> tag wraps the entire model definition.
  • <visual> / <statistic> configure the camera and visualization defaults.
  • <default> sets simulation-wide config: since drive wheels use continuously-rotating hinge joints, limited="false". armature is tuned for stability; equality values are generic solver parameters for contact physics.
  • Inside <worldbody>:
    • link_chassis is the base box, parent of everything else.
    • link_axle_left / link_axle_right attach directly to the chassis.
    • link_wheel_left / link_wheel_right attach to their axles via hinge joints (joint_axle_left_to_wheel_left, joint_axle_right_to_wheel_right).
    • link_support_caster → link_wheel_caster is a fixed (no joint) caster assembly.
  • <actuator> declares motor control for both drive-wheel hinge joints, with control ranges.
  • <contact> disables contact physics between each axle and its wheel (they'd otherwise collide with themselves).

Understanding the Robot Arm MJCF

  • Two default classes are defined: arm (joints + position actuators for arm links) and gripper (joints + position actuators for fingers). Both use limited="true" since arm rotation and gripper travel are bounded — unlike the continuously-spinning wheels.
  • armature/damping tune stability; kp (position gain) and forcerange configure the position controllers used for these joints.
  • Body chain: link_base_plate → link_base_dome (hinge) → link_arm1 (hinge) → link_arm2 (hinge) → link_arm3 (hinge) → link_base_gripper (fixed) → link_finger_left / link_finger_right (slide joints).
  • <actuator> uses position control (vs. the base's motor/velocity control) for all arm and gripper joints.
  • <contact> disables contact physics between each pair of directly-connected arm/gripper links.

Debugging: Why Is the Robot Buried in the Ground?

The robot loads partially buried inside the ground-plane. Here's why:

Look at how link_chassis is defined:

xml<body name="link_chassis" pos="0 0 0" euler="0 0 0">
    <geom type="box" size="0.150 0.100 0.050" rgba="1 0 0 1"/>
    <inertial pos="0 0 0" mass="3.000"
              diaginertia="0.012500000000000 0.025000000000000 0.032500000000000"/>
    <!-- rest of the model data -->

link_chassis has no joint defined, so it defaults to a fixed joint in MuJoCo. The ground-plane is also fixed, both at pos="0 0 0" — so they overlap.

The fix: the base needs to move, so it can't be fixed. Give it a free joint (6 degrees of freedom):

xml    <freejoint name="joint_world_to_chassis"/>
    <!-- rest of the model data -->

Add this <freejoint> line to link_chassis in robot_crane.mjcf, save, and relaunch:

terminal
cd ~/ros2_ws/mjcf ~/ros2_ws/mujoco/bin/simulate ./scene_robot_crane.mjcf

import os
import time
import mujoco
import mujoco.viewer
from threading import Thread

class RobotCraneSimulation:

   def __init__(self, model_path):
       # class constructor

       # get mjcf model path
       self.model = mujoco.MjModel.from_xml_path(model_path)
       # create variable to store simulation data
       self.data = mujoco.MjData(self.model)

       # create a passive viewer instance of mujoco
       self.viewer = mujoco.viewer.launch_passive(self.model, self.data)

       # boolean flag to hold simulation status
       self.sim_active = False

       # variables to hold sensor values
       self.ranges = {"front": 0.000, "back": 0.000,
                      "left": 0.000, "right": 0.000}
       self.imu = {"accelerometer": {"x": 0.000, "y": 0.000, "z": 0.000},
                   "gyroscope": {"x": 0.000, "y": 0.000, "z": 0.000},
                   "magnetometer": {"x": 0.000, "y": 0.000, "z": 0.000}}
       self.odom = {"position": {"x": 0.000, "y": 0.000, "z": 0.000},
                    "quaternion": {"w": 0.000, "x": 0.000, "y": 0.000, "z": 0.000}}

       # get actuator identification information
       # motors
       self.motor_left = self.model.actuator("wheel_left").id
       self.motor_right = self.model.actuator("wheel_right").id
       # arm controllers
       self.arm_base = self.model.actuator("arm_base").id
       self.arm_link1 = self.model.actuator("arm_link1").id
       self.arm_link2 = self.model.actuator("arm_link2").id
       self.arm_link3 = self.model.actuator("arm_link3").id
       # gripper controllers
       self.gripper_left = self.model.actuator("finger_left").id
       self.gripper_right = self.model.actuator("finger_right").id

       # variables to hold actuator values
       self.motor = {"left": 0.000,  "right": 0.000}
       self.arm = {"base": 0.000, "link1": 0.000, "link2": 0.000, "link3": 0.000}
       self.gripper = {"left": 0.000, "right": 0.000}

       return None

   def __del__(self):
       # class destructor

       # delete the viewer
       del self.viewer
       # delete the simulation data
       del self.data
       # delete the model information
       del self.model

       return None

   def start_simulation(self):
       # trigger function to start the simulation
       self.sim_active = True

       # start the simulation thread function
       self.sim_thread = Thread(target=self.run_simulation)
       self.sim_thread.start()

       # start the sensor data print thread function
       self.sensor_data_thread = Thread(target=self.print_sensor_data)
       self.sensor_data_thread.start()

       return None

   def run_simulation(self):
       # thread function to execute the simulation away from main thread

       while self.sim_active:
           try:
               mujoco.mj_step(self.model, self.data)
               self.viewer.sync()
               self.read_sensor_data()
               self.write_actuator_data()
           except:
               self.sim_active = False

       return None

   def read_sensor_data(self):

       # get range sensor values
       self.ranges["front"] = round(float(self.data.sensor("sensor_range_front").data[0]), 3)

       # get imu sensor values
       self.imu["accelerometer"]["x"] = round(float(self.data.sensor("sensor_imu_acc").data[0]), 3)
       self.imu["accelerometer"]["y"] = round(float(self.data.sensor("sensor_imu_acc").data[1]), 3)
       self.imu["accelerometer"]["z"] = round(float(self.data.sensor("sensor_imu_acc").data[2]), 3)
       self.imu["gyroscope"]["x"] = round(float(self.data.sensor("sensor_imu_gyr").data[0]), 3)
       self.imu["gyroscope"]["y"] = round(float(self.data.sensor("sensor_imu_gyr").data[1]), 3)
       self.imu["gyroscope"]["z"] = round(float(self.data.sensor("sensor_imu_gyr").data[2]), 3)
       self.imu["magnetometer"]["x"] = round(float(self.data.sensor("sensor_imu_mag").data[0]), 3)
       self.imu["magnetometer"]["y"] = round(float(self.data.sensor("sensor_imu_mag").data[1]), 3)
       self.imu["magnetometer"]["z"] = round(float(self.data.sensor("sensor_imu_mag").data[2]), 3)

       # get odom sensor values
       self.odom["position"]["x"] = round(float(self.data.sensor("sensor_odom_position").data[0]), 3)
       self.odom["position"]["y"] = round(float(self.data.sensor("sensor_odom_position").data[1]), 3)

       self.odom["quaternion"]["x"] = round(float(self.data.sensor("sensor_odom_orientation").data[1]), 3)
       self.odom["quaternion"]["y"] = round(float(self.data.sensor("sensor_odom_orientation").data[2]), 3)
       self.odom["quaternion"]["z"] = round(float(self.data.sensor("sensor_odom_orientation").data[3]), 3)

       return None

   def print_sensor_data(self):
       # thread function to print sensor data away from main thread

       while self.sim_active:
           print("~~~~~")
           print("Ranges:", self.ranges)
           print("IMU:", self.imu)
           print("Odom:", self.odom)
           time.sleep(1.0)

       return None

   def write_actuator_data(self):
       # function that writes actuator data to the simulation
       # modify class variables for actuators directly

       # set motor actuator values
       self.data.ctrl[self.motor_left] = self.motor["left"]

       return None

from robot_crane_interfaces.msg import Ranges

from robot_crane_interfaces.msg import Actuation

import mujoco
import mujoco.viewer
from threading import Thread


class RobotCraneSimulation(Node):

    def __init__(self):
        # class constructor
        super().__init__("robot_crane_simulation")
        self.get_logger().info("Initialized Node: robot_crane_simulation")

        # access model file path parameter
        self.declare_parameter("model_path", "default_value")
        self.model_path = self.get_parameter("model_path").value
        self.get_logger().info("Model Path: " + self.model_path)

        # callback group to hold publishers and subscribers
        self.callback_group = ReentrantCallbackGroup()

        # a common qos profile for both publisher and subscriber
        self.qos_default = QoSProfile(depth=10,
                                      reliability=ReliabilityPolicy.BEST_EFFORT,
                                      durability=DurabilityPolicy.VOLATILE)

        # ranges publisher
        self.ranges_pub = self.create_publisher(
            msg_type=Ranges, topic="/ranges",
            qos_profile=self.qos_default,
            callback_group=self.callback_group)
        self.get_logger().info("Initialized Publisher: /ranges")

        # odometry publisher
        self.odom_pub = self.create_publisher(
            msg_type=PosQuat, topic="/odometry",
            qos_profile=self.qos_default,
            callback_group=self.callback_group)
        self.get_logger().info("Initialized Publisher: /odometry")

        # imu publisher
        self.imu_pub = self.create_publisher(
            msg_type=AccGyrMag, topic="/accgyrmag",
            qos_profile=self.qos_default,
            callback_group=self.callback_group)
        self.get_logger().info("Initialized Publisher: /accgyrmag")

        # actuator subscriber
        self.actuator_sub = self.create_subscription(
            msg_type=Actuation, topic="/actuators",
            callback=self.actuator_callback,
            qos_profile=self.qos_default,
            callback_group=self.callback_group)
        self.get_logger().info("Initialized Subscriber: /actuators")

        # get mjcf model path
        self.model = mujoco.MjModel.from_xml_path(self.model_path)
        # create variable to store simulation data
        self.data = mujoco.MjData(self.model)

        # create a passive viewer instance of mujoco
        self.viewer = mujoco.viewer.launch_passive(self.model, self.data)

        # boolean flag to hold simulation status
        self.sim_active = False

        # variables to hold sensor values
        self.ranges = Ranges()
        self.pos_quat = PosQuat()
        self.acc_gyr_mag = AccGyrMag()

        # get actuator identification information
        # motors
        self.motor_left = self.model.actuator("wheel_left").id
        self.motor_right = self.model.actuator("wheel_right").id
        # arm controllers
        self.arm_base = self.model.actuator("arm_base").id
        self.arm_link1 = self.model.actuator("arm_link1").id
        self.arm_link2 = self.model.actuator("arm_link2").id
        self.arm_link3 = self.model.actuator("arm_link3").id
        # gripper controllers
        self.gripper_left = self.model.actuator("finger_left").id
        self.gripper_right = self.model.actuator("finger_right").id

        # variables to hold actuator values
        self.actuation = Actuation()

        # start the simulation process
        self.get_logger().info("Robot Crane MuJoCo Simulation Started!")
        self.start_simulation()

        return None

    def __del__(self):
        # class destructor
        return None

    def start_simulation(self):
        # trigger function to start the simulation
        self.sim_active = True

        # start the simulation thread function
        self.sim_thread = Thread(target=self.run_simulation)
        self.sim_thread.start()

        return None

    def run_simulation(self):

        while self.sim_active:
            try:
                mujoco.mj_step(self.model, self.data)
                self.viewer.sync()
                self.publish_sensor_data()
                self.write_actuator_data()
            except:
                self.sim_active = False

        return None

    def publish_sensor_data(self):

Key differences from the plain-Python version:

  • The model path is read as a ROS2 parameter (model_path), since after building, the file lives under install/, not src/.
  • Publishers push all sensor data to ROS2 topics (/ranges, /odometry, /accgyrmag); a subscriber on /actuators drives the robot.
  • The MuJoCo simulation runs in its own thread, since it can't live inside a ROS2 callback.
  • publish_sensor_data() replaces read_sensor_data() — sensor values are piped straight to topics instead of being stored.
